# 产品 PRD 汇编（I15）

> **纪律 1**：PRD 中出现的任何业务语义，必须能在 I5-I10 产物中找到对应条目。**PRD 不得成为语义的首次出现地。**
> **纪律 2**：业务方评审提出的新内容，必须回流 I5-I10 后重新汇编 PRD，禁止只改 PRD。受影响范围无代码基线时按 `common-workflow-changes.md` 就地协调；已有代码基线时按 `change-request-process.md` 执行 CR1-CR5。
> **纪律 3**：I15 只生成工作稿；PRD 仅可在 I16 通过后对外发出。

## 职责与执行时机

I15 是条件步骤：业务产物门禁完成后的无条件 PRD 决策检查点已由用户选择“需要”时才执行；选择“不需要”时记录依据，跳过 I15/I16 且不创建目录、PRD 或占位文件。I15/I16 必须在 I11 前完成，不按编号自然顺序执行。

PRD 是 I3-I10 业务产物的派生汇编视图，不是需求基线。首次业务 PRD 禁止纳入 I12 技术设计、系统交互时序图或其他技术设计章节。

## 汇编前置门禁

| # | 条件 | 不满足时 |
|---|------|----------|
| 1 | `scenario-manifest.md` 存在且模块映射已确认；§4-§8 非空或有合法不适用依据；§8 定位键符合固定格式、在对应模块/语义类型/来源路径内唯一且关联当前场景 FR；§9 每个索引区块的每条适用来源路径独立一行，状态均为 `current`，且记录的 `sha256:<64 位小写十六进制>` 等于来源文件原始 UTF-8 字节的 SHA-256 | 阻断；按缺口返回 I3 或对应来源步骤，更新 manifest 后重审 |
| 2 | 主模块业务产物门禁完成：I8 已通过；执行 I9 时 I10 也已通过；I9 不适用时已有依据 | 阻断 |
| 3 | 次要模块被依赖切片已完成对应 I5-I10 子集 | 允许继续，但对应章节“本章未覆盖内容”必须写明模块 ID、未覆盖内容和预计承接场景，禁止静默省略 |
| 4 | I5 澄清问题不存在未关闭阻断项 | 存在阻断项则阻断；待确认但非阻断项允许继续，但必须原样透传到“待确认问题”章节 |

检查 §9 时必须重新计算每个来源文件的 SHA-256。内容、路径或 §8 定位键变化时先将对应记录置为 `stale`，完成索引同步前不得继续。新增来源必须先以真实路径、修订标识 `—` 登记为 `stale`，同步完成并写入当前 SHA-256 后才能转为 `current`；删除来源保留证据行并置为 `stale`。`not-applicable` 行的来源路径和修订标识必须为 `—`，同步时间和依据必填；适用性变化时先转 `stale`，再补建逐来源的 `current` 记录。

## 场景切片与条件产物

PRD 范围只取 `scenario-manifest.md` 当前场景切片：FR 取 §4、契约取 §5、页面取 §6、章节取 §7，状态/字段/权限/数值/枚举取 §8，新鲜度取 §9。模块级 I5-I10 产物仅是权威内容来源，禁止将模块级全集汇入当前场景。§8 中未关联当前场景 FR、格式不合法或范围内重复的条目不得汇编。

每章汇编前必须判定来源为以下三态之一：

| 状态 | 处理 |
|------|------|
| 适用且存在 | 正常汇编并标注来源 |
| 不适用并有依据 | 保留章节和元信息，正文记录“不适用”及依据；不得创建空来源文件 |
| 应存在但缺失 | 阻断，返回对应 I 步骤补充并重审 |

## 溯源标注

PRD 每条业务语义必须定位到来源产物的具体条目。允许格式包括：

```text
[来源: M03-FR-007]
[来源: US-012 Scenario "门店停业时下架关联商品"]
[来源: operation-admin-page-specs.md §门店实例列表]
[来源: EXT-IN-003]
```

排版性导读和过渡句可不标来源，但必须与业务语义明确分离，不得承载规则、状态、字段、权限、数值、枚举、范围或验收含义。

## 零新增语义自检

输出 PRD 前必须展示逐项自检结果：

| # | 自检项 | 不通过处理 |
|---|--------|-----------|
| 1 | 无来源标注的业务语义数量是否为 0 | 阻断并分类：来源应存在但缺失则回对应 I 步骤补充并重审；汇编时臆造则直接删除，禁止反向补入 I5 |
| 2 | 是否存在为使章节完整而编写的推测性内容 | 阻断；有已确认输入但未进基线时转为待确认问题，纯臆造直接删除 |
| 3 | 排版性文字是否与业务语义分离 | 未分离时重写排版文字，不得掩盖无来源语义 |

## 产物路径与生命周期

- 多模块场景：`docs/aidlc/product/scenarios/<scenario-id>/prd.md`
- 单模块：`docs/aidlc/inception/prd.md`

```text
draft → consistency-checked（I16 通过）→ ready-for-review → confirmed
                                                    ↓ 业务方有意见
                                            回流 I5-I10 → 重新 I15/I16
```

任何来源变化都使受影响索引转为 `stale`，PRD 状态回退为 `draft`。业务方提出新语义时不得直接修改 PRD：无代码基线走在途协调，有代码基线走 CR；两者均须就地更新权威来源并重新执行受影响审查、I15 和 I16。

## 完成条件

- 四项前置门禁均满足或按规则显式处理；
- 每章完成三态判定，所有未覆盖内容均显式记录；
- 每条业务语义均有具体来源标注；
- 零新增语义自检全部通过并输出可见结果；
- PRD 状态为 `draft`，未对外发出；
- `scenario-manifest.md` §7、§9 和 `state.md` 已更新，下一步明确为 I16。
