## 1. 结论摘要

原评估发现的 10 项冲突和适用性缺口，已由提出方统一选择推荐方案 A，并写入 `aidlc-change-spec-conflict-decisions.md`。原规格已同步修复：

1. I15 统一以“主模块业务产物门禁完成”为前置条件，不再要求所有次要模块通过 I10。
2. 无 UI 场景可在 I8 通过且记录 I9 不适用依据后进入 I15。
3. “PRD 汇编时机”已修正为“PRD 对外发出时机”，消除 I15/I16 循环表述。
4. PRD 和 I16 均以 `scenario-manifest.md` 作为当前场景切片索引，不再比较模块级来源全集。
5. 条件产物统一采用三态判定：适用且存在、不适用并有依据、应存在但缺失。
6. 未关闭阻断项不得进入常规 I15；仅待确认但非阻断项允许透传。
7. 首次业务 PRD 不再包含 I12 技术设计章节。
8. 通用流程图和状态判定检查移入始终执行的审查项 b，基座状态机对照保留在 a。
9. 权限矩阵补充非 UI 合法表达和 FR 权限不适用记录。
10. 跨模块 FR ID 明确在模块内全局唯一，序号不得按场景重置。
11. PRD 决策检查点在业务产物门禁完成后无条件触发，不再依赖先进入 I15。
12. manifest 明确由 I3 初始化、I5/I6、I9/I10、I15 持续维护，并受新鲜度门禁约束。
13. C5-7 与 C6-5 统一先区分“来源应有但缺失”和“汇编臆造”，分别回上游补充或直接删除。
14. manifest §8 新增场景语义切片索引；状态、字段、权限、数值和枚举使用固定格式的复合来源定位键，要求范围内唯一并关联当前场景 FR，由 I5/I7 生成、I6/I8 审查。
15. manifest §9 新增来源版本与新鲜度证据；每个区块、每条适用来源路径独立记录，修订标识统一为文件原始 UTF-8 字节 SHA-256，并定义 `current` / `stale` / `not-applicable` 的必填字段和状态转换。

因此，当前规格已经从“有条件通过”提升为“**规格设计通过，可进入实施**”。该结论只评价规格文本，不代表 CH-01 至 CH-09 已实施，也不代表规格 §6 的端到端验收已执行。

## 3. 冲突关闭验证

### 3.1 CF-01：I15 模块完成范围

**状态**：已关闭。

当前规则明确：

- 主模块必须完成业务产物门禁；
- 次要模块未完成部分允许显式标注；
- C5-1、C5-4 和 D-01 语义一致。

### 3.2 CF-02：无 UI 场景路由

**状态**：已关闭。

“业务产物门禁完成”现定义为：

```text
I8 已通过；执行了 I9 时 I10 也已通过；I9 不适用时记录不适用依据。
```

该定义消除了纯后端、API、数据处理场景无法进入 I15 的问题。

### 3.3 CF-03：I15/I16 循环表述

**状态**：已关闭。

C5-8 已明确：I15 先生成工作稿，I16 通过后才能对外发出。汇编和发出时机不再混淆。

### 3.4 CF-04：场景切片与模块级来源

**状态**：已关闭。

当前规则以 `scenario-manifest.md` 为范围与证据索引：

- §4：FR；
- §5：契约；
- §6：页面；
- §7：PRD 章节；
- §8：状态、字段、权限、数值和枚举等场景语义切片；每条使用固定格式的复合来源定位键，在范围内唯一并关联当前场景 FR；
- §9：每个区块、每条适用来源路径独立记录原始 UTF-8 字节 SHA-256、RFC 3339 同步时间和新鲜度状态。

模块级 I5-I10 产物只提供权威内容，不再将其全集强制纳入单个场景 PRD。

### 3.5 CF-05：条件产物适用性

**状态**：已关闭。

C5、C6、C7 已使用统一三态：

| 状态 | 处理 |
|------|------|
| 适用且存在 | 正常汇编和审查 |
| 不适用并有依据 | 记录依据，不阻断，不创建空来源文件 |
| 应存在但缺失 | 阻断并返回对应步骤补充 |

### 3.6 CF-06：未关闭阻断项

**状态**：已关闭。

当前规则区分：

- 阻断项：不得通过 I6，不得进入常规 I15；
- 待确认但非阻断项：允许进入 I15，但必须完整透传。

### 3.7 CF-07：I12 与首次 PRD 时序

**状态**：已关闭。

I12 技术设计已从首次业务 PRD 映射中移除。系统交互时序图不再成为 I15 前置内容，也不会永久保留“待应用设计”章节。

### 3.8 CF-08：审查项 a 的适用范围

**状态**：已关闭。

- 存量基座状态机对照保留在条件执行的审查项 a；
- 流程图与 FR 映射、状态判定记录移到始终执行的审查项 b。

新项目和存量项目均会执行通用检查。

### 3.9 CF-09：非 UI 权限矩阵

**状态**：已关闭。

当前规则允许：

- `所在页面` 填写 `不适用（系统/API 操作）`；
- 非 UI 外部调用使用 `接口拒绝`；
- 无权限语义的内部系统事件进入固定的“FR 权限不适用记录”，不得虚构页面、按钮或角色。

### 3.10 CF-10：FR ID 作用域

**状态**：已关闭。

跨模块 FR ID 在模块内全局唯一并单调分配，序号不按场景重置；场景归属由 manifest 维护。

## 4. 当前设计合理性

### 4.1 PRD 的事实来源边界清晰

当前形成三层结构：

```text
模块级 I5-I10 产物：需求基线和权威内容
scenario-manifest.md：当前场景范围索引
prd.md：按场景生成的业务方汇编视图
```

该结构同时满足：

- 模块级产物可被多个场景复用；
- 单个 PRD 不混入其他场景内容；
- PRD 语义可反向定位到权威来源；
- 页面和需求不产生第二事实源。

### 4.2 路由规则具备可机械执行性

业务产物门禁、条件产物三态、阻断项分类和场景切片都具有明确判定条件，减少了 AI 自行推断空间。

I15/I16 虽然编号位于 I14 之后，但规格仍明确其逻辑时机位于业务产物门禁完成后、I11 之前，并在 I11 和 Construction 入场门禁中设置阻断条件。该兼容方案可接受。

### 4.3 防形式主义机制完整

以下机制共同降低“表面完整、语义缺失”的风险：

- 流程节点与 FR 双向映射；
- 状态建模触发条件及显式不适用记录；
- 权限矩阵按钮/入口级约束；
- PRD 每条业务语义的来源标注；
- I16 逐条溯源矩阵；
- 缺失与臆造使用不同修复路径；
- 数量型检查必须报告分子/分母。

### 4.4 向后兼容策略合理

保留 I1-I14，避免历史 `state.md`、审计和交接引用失效。历史项目仅在进入 I15 或相关 CR 时按受影响范围补建流程图、权限矩阵和场景索引，不追溯已完成且不再变更的 Construction 模块。

## 5. 实施阶段仍需关注的风险

以下不是规格阻断项，但必须在 CH-01 至 CH-09 实施时验证。

### 5.1 跨文件同步风险

规格涉及新建 2 个 steering 文件，并修改路由、状态模板、目录规范、门禁、术语和变更流程。实施时必须按改造项同步关联文件，避免只修改主规则。

### 5.2 大型场景审查规模

I16 需要读取 PRD 和多个模块的场景切片。大型场景应按 manifest 章节分批审查，再统一汇总 13 个检查点；不得以分批为由降低覆盖率或只输出聚合百分比。

### 5.3 场景索引维护风险

manifest 成为场景范围的关键索引。I5-I10 产物变更后，§4 至 §8 的范围与语义索引必须同步更新；§8 定位键须按固定格式生成、范围内唯一并关联 FR；§9 必须按每个区块、每条适用来源路径记录原始 UTF-8 字节 SHA-256、RFC 3339 同步时间和状态。重算哈希不一致或状态不是 `current` 时 I15/I16 必须阻断，不能基于过期切片产生结论。

### 5.4 非 UI 权限不适用记录

“权限不适用”不能成为逃避权限分析的通用出口。每条记录必须具备 FR、依据、确认人和日期，并由 I7 门禁验证。

## 6. 实施与验收建议

### 6.1 建议实施顺序

每个阶段同步更新对应 CH-09 内容，最后再执行全局一致性复核：

```text
阶段 1：CH-01 + 对应目录/状态/术语同步
阶段 2：CH-02 + CH-03 + CH-04 + 对应质量门禁同步
阶段 3：CH-08（a/b/c/e 审查项调整）
阶段 4：CH-05 + CH-07（PRD 汇编和模板）
阶段 5：CH-06（I16 一致性审查）
阶段 6：CH-09 全局复核
```

### 6.2 必须执行的验证场景

除规格 §6 原有场景外，实施后至少验证：

1. 跨两个模块且包含 UI，次要模块部分未完成；
2. 单模块且无 UI，在 I8 后正常进入 I15；
3. 同一模块被两个场景复用，PRD 不混入另一场景的 FR 和页面；
4. 条件产物合法不适用时不误阻断，应存在但缺失时正确阻断；
5. 未关闭阻断项无法进入常规 I15；
6. 首次业务 PRD 不包含 I12 技术设计章节；
7. 非 UI FR 使用权限不适用记录且不虚构角色；
8. 同一模块跨场景的 FR ID 不重复；
9. 不选择 PRD 时不创建 `prd.md` 或占位产物；
10. 业务产物门禁完成后无条件出现 PRD 决策检查点，选择不需要时正常继续 I11；
11. manifest §8 的复合来源定位键格式错误、范围内重复或未关联当前场景 FR 时，I6/I8 与 I15/I16 正确阻断；
12. 同一区块关联多条来源路径时 §9 逐路径记录；重算原始 UTF-8 字节 SHA-256 不一致或适用来源状态不是 `current` 时，I15/I16 正确阻断；
13. §9 `not-applicable` 行按规则填写 `—`、同步时间和依据，适用性变化时先转 `stale` 再补建 `current` 记录；
14. 无来源内容属于上游缺失时回对应步骤补充，属于汇编臆造时直接删除且不污染 I5。

### 6.3 完成声明边界

只有以下条件全部满足，才能声明改造完成：

- CH-01 至 CH-09 已写入对应事实来源；
- §4 关联文件全部同步；
- §6.1 静态一致性全部通过；
- §6.2 端到端演练实际执行并有证据；
- §6.3 反向验证全部通过；
- 无 TODO、FIXME、空实现或未经验证的能力声明。

当前只完成了**规格修复和合理性复评**，尚未实施 steering，也未执行上述端到端验收。
