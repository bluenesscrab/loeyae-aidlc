## 2. CF-01：I15 要求所有模块通过还是仅主模块通过

### 原文位置

- **C5-1**：`用户选择产出 PRD 且场景涉及模块的 I10 均已通过`
- **C5-4 条件 2/3**：主模块 I10 已通过；次要模块未完成时允许继续但必须显式标注。
- **D-01**：主模块 I10 通过即可汇编 PRD；次要模块未完成部分显式标注。

### 冲突原因

C5-1 要求场景涉及的所有模块均通过 I10，而 C5-4 和最终决策 D-01 明确允许次要模块尚未完成。两套条件不能同时成立：

```text
C5-1：主模块通过 + 所有次要模块通过 → 才能进入 I15
D-01：主模块通过 + 次要模块可未完成 → 可以进入 I15
```

按照规格 §7 的优先级声明，应以 D-01 为准，但原规格仍需统一措辞，否则执行 AI 可能选择更严格的 C5-1 并错误阻断。

### 影响

- 次要模块未完成时，I15 是否可执行没有唯一答案。
- C5-1 的路由条件与 C5-4 的门禁处理会产生不同执行结果。
- §6.2 的端到端演练无法确定应构造“全部模块完成”还是“仅主模块完成”的场景。

### 处理方案

**方案 A（推荐）**：以 D-01 为准。I15 只要求主模块适用门禁通过；次要模块未完成部分必须按模块 ID、未覆盖内容和预计承接场景显式标注。

**方案 B**：改为所有涉及模块均完成后才能汇编，同时修改 D-01。这会提高完整性，但违背已确认的业务评审时效目标。

### 推荐写回原规格的文本

```text
| I15 | PRD 汇编 | 用户选择产出 PRD，且主模块适用的 I5-I10 门禁已通过；次要模块未完成部分按 D-01 显式标注 | 🔴 | `product-prd-assembly.md` |
```

### 回答位置

```text
【提出方回答 CF-01】
选择：方案 A
补充说明：接受推荐方案，以 D-01 为准，仅要求主模块适用门禁通过。
```

## 3. CF-02：无 UI 场景无法满足 I10 前置条件

### 原文位置

- **现有路由 I9**：仅在用户选择且存在界面需求时执行。
- **现有路由 I10**：仅在 I9 已执行时执行。
- **C5-2 / D-03**：I15/I16 在 I10 完成后、I11 之前执行。
- **C5-4 / D-01**：主模块 I10 必须通过。

### 冲突原因

纯后端、API、批处理、数据迁移等需求可能不执行 I9，因此也不会执行 I10。若 I15 强制要求 I10 通过，这些场景永远无法产出 PRD。

```text
无 UI → I9 不适用 → I10 不执行 → I15 前置条件永远不成立
```

这不是简单措辞问题，而是路由不可达问题，并涉及最终决策 D-01、D-03 的补充解释。

### 影响

- 无 UI 项目无法使用新增 PRD 能力。
- “PRD 是条件产物”的能力范围被意外缩小为仅 UI 场景。
- I11 的新增前置条件可能永久阻断后续 Inception。

### 处理方案

**方案 A（推荐）**：使用“业务产物门禁完成”作为统一条件：I8 必须通过；若执行 I9，则 I10 也必须通过；若 I9 不适用，则记录不适用依据后可进入 I15。

**方案 B**：限制 PRD 仅用于存在 UI 的需求。该方案需要在改造目标中明确缩小能力范围，不符合当前“PRD 原生条件产物”的普遍描述。

### 推荐写回原规格的文本

```text
I15/I16 在业务产物门禁完成后、I11 之前执行：I8 必须通过；执行了 I9 时 I10 也必须通过；I9 不适用时记录不适用依据。
```

需同步修改 C5-1、C5-2、C5-4、C5 验收、D-01、D-03、C9-1 和 §6.2。

### 回答位置

```text
【提出方回答 CF-02】
选择：方案 A
补充说明：采用“业务产物门禁完成”；I9 不适用时在 I8 通过后进入 I15。
```

## 4. CF-03：PRD 汇编时机与 I16 形成循环表述

### 原文位置

**C5-8 第 3 条**：

> PRD 汇编时机为 I16 通过后方可对外发出。此前只允许存在工作稿。

### 冲突原因

I16 审查的输入是 I15 已汇编出的 PRD。若将 I16 通过定义为“汇编时机”，会形成循环依赖：

```text
必须先 I16 通过才能汇编 PRD
但必须先汇编 PRD 才能执行 I16
```

结合后半句判断，原意应当是“对外发出时机”，而不是“汇编时机”。

### 影响

- 执行 AI 可能错误阻止 I15 生成工作稿。
- I15 与 I16 的顺序不再可执行。

### 处理方案

**方案 A（推荐）**：作为文字勘误，将“PRD 汇编时机”改为“PRD 对外发出时机”。

**方案 B**：另行定义预汇编产物和正式汇编产物。该方案会增加不必要的双产物状态，不推荐。

### 推荐写回原规格的文本

```text
PRD 对外发出时机为 I16 通过后。在 I16 通过前，I15 只能生成工作稿，工作稿禁止发给业务方。
```

### 回答位置

```text
【提出方回答 CF-03】
选择：方案 A
补充说明：确认属于文字勘误，改为“PRD 对外发出时机”。
```

## 5. CF-04：场景级 PRD 与模块级来源全集比较冲突

### 原文位置

- **C1-9**：PRD 按场景生成，I5-I10 产物按模块归档；同一模块可被多个场景复用。
- **C6-3 检查点 2**：`requirements.md` 的 FR 全集必须在 PRD 中体现。
- **C6-3 检查点 5**：PRD 页面清单与 `page-specs` 页面集合完全相同。
- **C6-3 检查点 7-10**：状态、字段、权限、数值与来源产物比较，但未限定场景切片。

### 冲突原因

PRD 是场景级视图，而来源文件是模块级基线。若同一个模块服务多个场景，模块级文件会包含其他场景的 FR、页面、字段和角色操作。按“全集完全相同”比较，会把其他场景内容错误纳入当前 PRD。

示例：

```text
模块 M03 requirements.md：
- M03-FR-001（场景 S01）
- M03-FR-002（场景 S02）

当前生成 S01 的 PRD：
- 正确范围应只有 M03-FR-001
- 现有检查点 2 却要求 M03-FR-001、M03-FR-002 全部进入 PRD
```

### 影响

- 场景边界失效。
- PRD 会混入无关需求和页面。
- 同一模块被多个场景复用的目标无法成立。

### 处理方案

**方案 A（推荐）**：以 `scenario-manifest.md` 作为场景切片索引，再到模块级权威产物验证：

- FR 范围取 manifest §4；
- 契约范围取 §5；
- 页面范围取 §6；
- PRD 章节范围取 §7；
- 状态、字段、权限和数值仅比较这些索引条目关联的内容。

**方案 B**：每个场景创建独立模块级产物。该方案违反 C1-9 的模块归档和复用原则，不推荐。

### 推荐写回原规格的文本

```text
审查项 g 的比较范围以 scenario-manifest.md 中当前场景的 FR、契约、页面和 PRD 映射索引为准。模块级来源产物仅作为权威内容来源，不将其全集视为当前场景范围。
```

### 回答位置

```text
【提出方回答 CF-04】
选择：方案 A
补充说明：以 scenario-manifest.md 作为场景切片索引，模块级产物仅作为权威内容来源。
确认人：提出方（本次对话确认）
确认日期：2026-08-07
```

## 6. CF-05：I16 对条件产物缺少不适用规则

### 原文位置

- **C5-5**：PRD 映射表包含状态模型、页面清单、交互说明、字段规格、I12 时序图等条件内容。
- **C6-2**：将 `data-model.md`、`page-specs`、澄清问题文件等直接列为输入。
- **C6-3**：要求逐项检查页面、状态、字段等内容。

### 冲突原因

这些来源并非所有场景都存在：

- 不涉及状态时可以合法没有状态图；
- 最小/标准深度可能没有完整实体字段模型；
- 无 UI 场景没有 `page-specs`；
- 清晰需求可能没有澄清问题文件；
- 首次 I15 位于 I12 之前，不会存在 I12 时序图。

当前规格没有区分“合法不适用”和“应存在但缺失”，可能把合法缺失误判为阻断。

### 影响

- 无状态、无 UI、无澄清问题的正常场景可能无法通过 I16。
- 不同 AI 可能自行推断不适用规则，导致执行结果不一致。

### 处理方案

**方案 A（推荐）**：每个章节和检查点使用三态判定：

```text
适用且存在：执行一致性检查
不适用并有依据：记录不适用，不阻断
应存在但缺失：阻断，回到对应步骤补充
```

**方案 B**：强制所有来源文件始终生成。该方案会制造空文件或占位内容，违反目录规范，不推荐。

### 推荐写回原规格的文本

```text
I16 对每项来源先判定适用性。合法不适用必须记录依据，不创建空产物；触发条件成立但产物缺失时阻断。
```

### 回答位置

```text
【提出方回答 CF-05】
选择：方案 A
补充说明：条件产物采用“适用且存在 / 不适用并有依据 / 应存在但缺失”三态判定。
确认人：提出方（本次对话确认）
```

## 7. CF-06：未关闭阻断项是否允许进入 PRD

### 原文位置

- **C5-4 条件 4**：I5 存在未关闭阻断项时允许继续汇编，但必须透传到 PRD。
- **C6-3 检查点 11**：只检查未关闭项是否完整透传。
- **C5-10**：I16 通过后可进入 `consistency-checked → ready-for-review`。

### 冲突原因

正常流程要求 I6 通过后才能进入 I7-I10。若 I5 仍存在真正的阻断项，I6 理论上不应通过，也不应到达 I15。

即使允许生成内部工作稿，C6 当前只验证“是否透传”，没有规定未关闭阻断项是否阻止 PRD 进入 `ready-for-review`。这可能出现“内容完全一致但业务仍未确认”的 PRD 被对外发出。

### 影响

- “阻断”语义被弱化为普通提示。
- PRD 可能在关键业务问题未解决时进入业务评审。
- I6、I15、I16 三个门禁的职责边界不清晰。

### 处理方案

**方案 A（推荐）**：区分两类问题：

- 待确认但非阻断：允许进入 I15，并在 PRD 中披露；
- 阻断项：不得通过 I6，也不得进入常规 I15；如业务需要内部工作稿，工作稿保持 `draft-blocked`，不得进入 `consistency-checked` 或 `ready-for-review`。

**方案 B**：允许阻断项进入 I15 和 I16，但即使 I16 一致性通过，也必须保持 `draft`，直至阻断项关闭后重跑受影响步骤。该方案可保留内部工作稿，但状态规则更复杂。

### 推荐写回原规格的文本

```text
未关闭阻断项不得进入可对外评审状态。若允许生成内部工作稿，必须使用阻断状态并在阻断项关闭后重新执行受影响步骤、I15 和 I16。
```

### 回答位置

```text
【提出方回答 CF-06】
选择：方案 A
补充说明：阻断项不得通过 I6 或进入常规 I15；仅非阻断待确认项允许透传。
确认人：提出方（本次对话确认）
```

## 8. CF-07：I15 在 I12 前执行但 PRD 引用 I12 产物

### 原文位置

- **C5-2**：I15/I16 在 I10 后、I11 前执行。

## 9. CF-08：通用流程与状态检查被放入条件审查项 a

### 原文位置

- **审查项 a 的执行条件**：存在逆向工程产物时执行。

- 检查点 8 保留在 a；
- 检查点 6/7 移到始终执行的审查项 b、独立需求完整性门禁，或新增始终执行的检查组。

**方案 B**：将审查项 a 改为始终执行，并对逆向工程相关检查点单独判定不适用。该方案改动范围较大。

## 10. CF-09：非 UI FR 无法自然填写按钮级权限矩阵

### 原文位置

- **C4-2**：固定表头包含“所在页面”；操作粒度到按钮/入口级；无权表现四选一。
- **C4-3**：每个 FR 至少被一行矩阵条目关联。
- **D-05**：按钮/入口级粒度为最终决策。

### 冲突原因

系统事件、API 消费方、定时任务和纯后端 FR 可能没有页面或按钮。若仍要求每个 FR 关联权限矩阵，执行 AI 只能留空、虚构页面或错误套用 UI 规则。

### 影响

- 非 UI 场景可能无法完成 I7。
- 为满足固定表头可能产生虚构内容。
- `无权表现` 的 UI 选项不一定适合系统内部动作。

### 处理方案

**方案 A（推荐）**：保持 D-05 和固定表头不变，增加合法值：

- `所在页面`：无 UI 时填 `不适用（系统/API 操作）`；
- `无权表现`：外部调用使用 `接口拒绝`；
- 无权限语义的内部系统事件记录“不适用依据”，不虚构无权角色。

**方案 B**：将权限矩阵改为仅覆盖有人机入口的 FR，其他 FR 在独立系统权限表中表达。该方案会增加新产物，不推荐作为首选。

### 回答位置

```text
【提出方回答 CF-09】
选择：方案 A
补充说明：保持 D-05 和固定表头，补充非 UI 场景的合法取值与不适用依据。
确认人：提出方（本次对话确认）
确认日期：2026-08-07
```

## 11. CF-10：跨模块 FR ID 的序号作用域不明确

### 原文位置

**C1-8**：跨模块场景的 FR 编号格式为 `<MODULE>-FR-<序号>`。

### 冲突原因

规格没有说明 `<序号>` 是在模块内全局递增，还是每个场景从 001 重新开始。若每个场景重新编号，同一模块参与多个场景时可能出现重复 ID：

```text
场景 S01：M03-FR-001
场景 S02：M03-FR-001
```

这会破坏 PRD 溯源、manifest 索引和 I16 悬空引用检查。

### 影响

- FR ID 不再全局唯一。
- PRD 来源标注无法唯一定位。
- 同一模块多场景复用时产生冲突。

### 处理方案

**方案 A（推荐）**：FR ID 在模块内全局唯一并单调分配；场景通过 manifest 索引 FR，不重置序号。

**方案 B**：把场景 ID 加入 FR ID，例如 `<MODULE>-<SCENARIO>-FR-<序号>`。定位更直接，但会改变 C1-8 已规定的格式，并使 FR 在场景间迁移时 ID 不稳定。

### 推荐写回原规格的文本

```text
跨模块项目的 FR ID 在模块内全局唯一，序号不得按场景重置。场景归属通过 scenario-manifest.md 维护，不编码进 FR ID。
```

### 回答位置

```text
【提出方回答 CF-10】
选择：方案 A
补充说明：FR ID 在模块内全局唯一，序号不得按场景重置。
确认人：提出方（本次对话确认）
确认日期：2026-08-07
```
