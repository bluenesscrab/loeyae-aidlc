# AI-DLC 对接 SSOT 文档平台改造实施计划(重定位基线)

> 重定位声明(2026-07-27):本文件已按 SSOT 重定位基线 `../../../loeyae-ssot-server/docs/aidlc/product/realignment-plan.md` 重写。
> 旧计划(Legacy/Mirror/Federated 多模式、state v3 迁移、Manifest/事件、双仓契约治理与 Provider-first 前滚、7 阶段控制平面发布、F008 需求审批端到端脚本)整体作废。以下为对齐后的简化实施计划。

关联文档:[01-改造需求.md](./01-改造需求.md)、[02-改造设计.md](./02-改造设计.md)、SSOT 契约 `../../../loeyae-ssot-server/docs/aidlc/modules/ssot/inception/mcp-contract.md`。

## 1. 计划目标

以向后兼容方式,让 AI-DLC 作为 SSOT 文档平台的 **MCP 消费方**:先实现只读检索,再实现正式/逆向文档写回,最后完成三平台适配。未配置 SSOT 的项目不受影响。单仓、无契约版本治理、无多模式。

## 2. 实施原则

1. 先只读后写入;
2. state 本地恢复优先,**保持 v2**;
3. SSOT 接入为可选,未配置时零影响;
4. 三平台共享语义,平台差异封装在 MCP 客户端/Hook 适配层;
5. 每阶段验证"未接入 SSOT"回归;
6. 以 SSOT `mcp-contract.md` 的 14 工具为唯一契约,不做双仓契约版本治理。

## 3. 改造范围

### 3.1 AI-DLC 侧(本仓)
- 新增 `common-ssot-integration.md` 共享规则;
- `core-workflow.md`/`inception-workspace-detection.md` 增加可选 SSOT 连接检测与项目绑定;
- `inception-state-template.md` 增加可选 SSOT 连接小节(仍 v2);
- 相关 Inception/CR steering 增加检索上下文与正式/逆向文档写回;
- 平台无关 `SsotDocClient` 封装(检索/读取/写回);
- Kiro/Claude/OpenCode 的 MCP 客户端配置与可选 SessionStart 可达性探测。

### 3.2 不在本改造中实现
- SSOT 后端与 Portal 本身(属 loeyae-ssot-server);
- 向量/检索算法、embedding/rerank 模型;
- 企业身份平台、CI、任务系统、部署平台;
- 控制平面工具、Manifest、事件、state 迁移、契约版本治理(已从范围删除)。

## 4. 阶段规划

### A0:接入准备
**目标**:确定连接与契约,建立回归基线。
**任务**:
- 固化"未接入 SSOT"的三平台关键场景回归样本;
- 对齐 SSOT `mcp-contract.md`(14 工具、header 鉴权);
- 约定 API Key 来源(环境变量/平台安全凭据)。
**门禁**:
- 未接入 SSOT 的行为有可重复回归;
- MCP 契约以 SSOT 现行 `mcp-contract.md` 为唯一来源。

### A1:连接、绑定与共享规则
**目标**:引入可选 SSOT 连接,不改变默认流程。
**任务**:
- 新增 `common-ssot-integration.md`;
- `core-workflow.md` 按需加载入口;
- `inception-workspace-detection.md`/I1 增加可选 SSOT 项目绑定;
- state 增加可选 SSOT 连接小节(v2,不含密钥)。
**验收**:
- 未配置 SSOT 的项目行为不变;
- 已配置时能解析 project 与当前用户角色;
- API Key 不落入 state/审计。

### A2:只读检索消费
**目标**:三平台可从 SSOT 检索同一批文档作上下文。
**任务**:
- 实现 `SsotDocClient` 的 `search`/`get`/`get_file`;
- 在 I5/I12 等需要既有资料的步骤接入检索并标注来源;
- SSOT 不可用时降级(标记暂不可用,不伪造)。
**验收**:
- 三平台同一查询返回同一 SSOT 文档来源;
- 检索片段带来源可溯源;
- 不可用时本地流程不受影响。

### A3:正式/逆向文档写回
**目标**:AI-DLC 产出可沉淀回 SSOT。
**任务**:
- 实现 `write_formal`/`write_reverse`;
- Inception 正式文档定稿并经用户确认后写回(type=formal);
- 逆向工程产出写回(type=reverse,关联 Git commit);
- 写回失败记"待写回"并可重试。
**验收**:
- 正式文档写回后可被 `search_documents` 命中;
- 逆向文档关联 Git 信息;
- 写回失败不阻断本地产物;
- 内容更新以新版本写回(无增量/patch)。

### A4:三平台适配与回归
**目标**:Kiro/Claude/OpenCode 一致,且未接入项目零影响。
**任务**:
- 三平台 MCP 客户端配置与可选 SessionStart 可达性探测;
- 平台差异封装在适配层;
- 完成未接入 SSOT 的回归与启用 SSOT 的核心场景。
**验收**:
- 三平台语义一致;
- 未接入 SSOT 回归通过;
- 鉴权失败/权限拒绝正确处理且不绕过。

## 7. 测试与验证矩阵

### 7.1 维度
| 维度 | 取值 |
|---|---|
| 平台 | Kiro / Claude Code / OpenCode |
| 项目类型 | 新项目 / 存量项目 |
| SSOT | 未配置 / 已配置 |
| 连接 | 在线 / 超时 / 不可用 / 恢复 |
| 鉴权 | 有效 / 无效 Key / 无项目权限 |

### 7.2 必测场景
1. 未配置 SSOT 的项目全流程回归;
2. 启用 SSOT 后 `search_documents` 取上下文并标注来源;
3. 正式文档 `write_formal_document` 写回后可检索命中;
4. 存量项目 `write_reverse_engineering` 写回并关联 Git;
5. SSOT 步骤中途不可用,本地恢复与检索/写回降级;
6. 无效 Key/无项目权限被拒且不绕过重试。

### 7.3 门禁
- 未接入 SSOT 回归;
- MCP 调用契约测试(对齐 14 工具);
- 检索来源标注与写回幂等;
- 鉴权/权限负向测试;
- 三平台一致性。

## 8. 发布与回退

- 分两步开启:先只读检索(A2),再文档写回(A3);
- 未配置 SSOT 的项目默认零影响;
- 关闭 SSOT 连接即回纯本地流程,已写回文档留在 SSOT;
- 无 Feature Flag 分级、无多模式切换、无 state 迁移。

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| AI-DLC 规则被 SSOT 逻辑污染 | 共享 steering 条件加载 + 平台无关 `SsotDocClient` |
| state 与 SSOT 双主 | state 只管执行,SSOT 只管文档正文 |
| 离线无法工作 | state 优先恢复,检索/写回降级不伪造 |
| 检索片段被当权威事实 | 片段仅参考,来源标注,不自动进入批准基线 |
| 多平台行为不一致 | 共享语义测试 + 适配层 |
| 写回重复 | 依赖 SSOT 的 (document_id, sha256) 幂等 |
| 凭据泄露 | API Key 经 header,不入 state/审计/提示词 |

## 10. 完成定义

1. 需求与设计中的必需项均有实现或明确的不适用依据;
2. 未接入 SSOT 的回归通过;
3. 三平台完成检索消费与文档写回核心场景;
4. SSOT 不可用/超时/鉴权失败场景通过;
5. 真实测试与证据可复现;
6. 未执行项明确标记未验证,不以文档审阅代替运行结果。
